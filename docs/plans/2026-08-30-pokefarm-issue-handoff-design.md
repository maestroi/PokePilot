# Pokéfarm issue handoff

**Date:** 2026-08-30
**Status:** Approved
**Scope:** Preserve enough evidence from long or crashed farm runs for a coding agent to investigate them, automatically submit every qualifying failure to Agent Orchestrator, and keep the returned issue number/status synchronized in Pokéfarm.

## Problem

Pokéfarm can run many seeds, retain durable finish dumps, and group failures
by normalized detail. That is enough to notice recurring problems, but not to
fix them. The wall currently stores only a final state and trace tail, the farm
does not enable `agent.Run`'s per-objective checkpoint ring, and the browser
cannot hand evidence to the local Agent Orchestrator.

Agent Orchestrator's external issue intake accepts a source-neutral multipart
report, runs a read-only investigation, and may create an operator-approved
draft repair plan. Pokéfarm should be one reporter of that API, not embed a
coding agent or duplicate issue lifecycle state.

## Boundary

```
farm runner --finish/checkpoints--> pokewall --durable dump + outbox
                                      |
qualifying error/lost run -----------|
                                      |
                                      +--issue report--> Agent Orchestrator :8080
                                                           |
                                      issue #42 + UUID <----+
                                      |
browser <--- Pokéfarm link to Agent Orchestrator UI :8081
```

- The runner observes gameplay and creates bounded objective and periodic checkpoints.
- The wall owns durable run evidence, failure grouping, and the outbound issue
  submission.
- `pokeui` remains an allowlisted browser relay. The browser never calls the
  unauthenticated Agent Orchestrator controller directly.
- Agent Orchestrator assigns the issue number. Pokéfarm stores the UUID for
  linking and displays `#<issue_number>`.
- Code changes still happen only through Agent Orchestrator's normal draft
  Plan → publish/start → coding → review → delivery workflow.

## Evidence bundle

For LLM farm runs, enable the existing `agent.Budget.CheckpointDir` ring with
the existing default of 16 objective checkpoints. Add a rolling flight recorder
that captures a state every 18,000 emulated frames (five minutes at 60 fps) and
keeps the latest 12 locally. The implementation must first prove that
`SaveState` from the existing sample callback is a safe frame-boundary operation;
if that measurement fails, add a deliberate emulator frame-boundary callback
rather than saving concurrently.

The runner uses a fresh temporary directory per lease. Objective checkpoints
retain paired knowledge. Periodic states also record the current objective,
question/decision, frame/map/tile, trace, and latest paired objective checkpoint.

Every finished run reports:

- run ID and attempt;
- exact runner build SHA;
- requested seed and resolved seed burn;
- reason/detail and trace tail;
- final save state;
- latest frame PNG when the wall can fetch it;
- each retained pre-objective state and paired knowledge file;
- each retained periodic flight-recorder state and metadata;
- a small manifest naming byte length, media type, and SHA-256 for every
  artifact.

The ROM is never included. Artifacts are bounded by the 16-entry checkpoint
ring and wall-side upload limits. Scripted runs keep the final state and trace
but have no objective checkpoints.

`farm.Artifact` is a wire type with `name`, `media_type`, `sha256`, and `data`.
Names are generated by PokePilot, not accepted from the model or run ID. The
wall validates name uniqueness, size, and SHA before accepting Finish.

The runner uploads new checkpoints through a separate bounded checkpoint route
as they appear. The sample callback only copies completed state bytes into a
capacity-one channel; an uploader goroutine performs filesystem/network work
and never touches emulator/RAM APIs. The wall retains the latest three periodic
states plus the latest complete objective state/knowledge pair, so a dead runner
still leaves evidence close to a failure three hours into a run.

The finish dump remains the durable source of truth for graceful completion. It may encode artifact
bytes in JSON for this first version; the wall never reconstructs collision
geometry or interprets save-state bytes.

## Failure identity and issue numbering

The wall already normalizes changing hex values and numbers in failure detail.
Add a stable failure key:

```
key = first 16 lowercase hex characters of SHA-256(normalized pattern)
```

The full normalized pattern is sent as evidence; the key is safe in URLs and
becomes the Agent Orchestrator report fingerprint `sha256:<full digest>`.
Issue deduplication therefore remains stable across run IDs, coordinates,
frames, and restarts.

Agent Orchestrator returns:

- internal issue UUID;
- project-local `issue_number`;
- current issue status;
- whether this occurrence was deduplicated.

Pokéfarm persists an `IssueLink` by failure key:

```json
{
  "issue_id": "...",
  "issue_number": 42,
  "issue_url": "http://192.168.50.81:8081/issues/...",
  "last_reported_run": "run-2f",
  "updated_at": 1788080000
}
```

The wall never allocates or increments issue numbers itself. History rows and
failure groups show linked `#42`; the link target uses the UUID, so numbers are
only the human-facing project-local identity.

## Automatic intake and operator flow

Every finished `error` or `lost` run with non-empty detail enters a durable wall
outbox after its dump is written. Clean completion, cooperative cancellation,
and ordinary budget exhaustion do not. The outbox retries with bounded backoff
until Agent Orchestrator accepts the idempotent occurrence. Initial capture is
automatic; an operator click is never required to preserve evidence.

Agent Orchestrator groups exact fingerprints, counts occurrences, and starts
read-only investigation at three matches (or immediately for critical reports).
Pokéfarm does not duplicate that policy.

Add a **Failures** section to the existing console using the wall's triage
groups. Each group shows count, normalized pattern, latest example, linked
issue number/status if any, and one action:

- **Pending report** while the durable outbox waits;
- **Issue #42 · open/investigating/fixed** after acceptance;
- **Investigate now** when an open issue is below the automatic threshold;
- **Retry report** after a network or validation failure.

The same issue badge appears on matching failed history rows and in their
detail pane.

Automatic reporting:

1. After Finish is durably dumped, or a lost run is settled with retained flight-recorder evidence, the wall enqueues an occurrence in its persisted outbox.
2. A background dispatcher re-resolves the group and chooses the newest
   finished representative whose durable dump exists.
3. The wall builds an Agent Orchestrator report with source `pokefarm`,
   fingerprint, external ID `<run-id>-attempt-<n>`, runner revision, run/tile/
   planner evidence, and the stored artifacts.
4. The wall posts the report. Agent Orchestrator decides whether occurrence count/severity starts investigation and returns issue number/status.
5. The wall persists the link and completes the outbox entry.
6. A low-frequency status sync refreshes linked issues. Fixed issues leave the active failure list but remain in history.

**Investigate now** is a threshold override only. Browser → `pokeui` → wall
requests investigation for an already linked issue; it never files the issue.

Network retries are safe because the external occurrence ID
and manifest are idempotent. A later representative from the same group becomes
a new occurrence on the same issue.

Successful verified delivery in Agent Orchestrator resolves the issue `fixed`
at an exact integration SHA. Pokéfarm mirrors that state; it does not declare a
fix locally. Any later qualifying run with the same fingerprint is reported
automatically, causing Agent Orchestrator to reopen the same numbered issue.

## Configuration

The wall receives:

- `-issues-api`, for example `http://192.168.50.81:8080`;
- `-issues-project`, the Agent Orchestrator PokePilot project UUID;
- `-issues-ui`, for example `http://192.168.50.81:8081`;
- `-issues-timeout`, default 30 seconds.

All three address/project values are required to enable issue handoff. Empty
configuration leaves current farm behavior and UI unchanged. The wall uses a
dedicated HTTP client with finite connect/request timeouts and never holds
`w.mu` during dump reads, hashing, or network calls.

The Swarm stack passes these from environment variables. No token is added in
this slice because the local Agent Orchestrator currently has no authentication;
documentation must call out that both services remain LAN-only.

## Errors

- No integration configuration: automatic reporting/status controls disabled, farm otherwise unchanged.
- Unknown/stale failure key: `404`; no report.
- Group has no durable representative dump: `409` with a clear message.
- Dump/artifact corruption or hash mismatch: `500`; do not submit partial data.
- Agent Orchestrator unreachable/timeout: `502`; retain the group and allow retry.
- Wall restart retains issue links and outbox entries in `state.json`; in-flight requests become retryable.
- Status sync failure leaves the last known status visible with a stale marker.

## Testing

- Runner tests prove objective/periodic checkpoints are bounded, paired where
  applicable, hashed, uploaded without concurrent emulator reads, and cleaned up.
- Farm contract tests round-trip build SHA, seed burn, and artifacts.
- Wall tests prove stable fingerprinting, newest durable representative
  selection, link persistence, no lock during upstream calls, idempotent retry,
  and partial-success behavior.
- PokeUI tests pin the single new allowlisted POST route and continue rejecting
  arbitrary proxying.
- UI tests cover hidden/disabled/loading/error/linked states and safe text/link
  rendering.
- End-to-end test runs wall + fake Agent Orchestrator over `httptest`, submits a
  representative dump, and verifies the issue number appears in dashboard and
  survives wall state reload.
- Farm infrastructure verification remains ROM-free:
  `env -u POKEMON_RED_ROM go test ./...`.

## Out of scope

- Automatically starting repair Plans
- High-frequency polling or streaming Agent Orchestrator state
- Uploading the ROM
- Teaching Pokéfarm Agent Orchestrator's database or task schema
- Reading or rendering save-state/collision bytes in the wall or browser
